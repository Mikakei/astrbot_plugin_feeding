# 完整配置与环境说明

[返回首页](../README.md)

基于 AstrBot 的 AI 投喂生图插件。结合用户上传的角色设定图和食物图片绘图，沿用触发会话当前生效的人格生成点评，最后将点评与图片放在同一条回复中。每次按本次投喂内容生成，不是预制图库；耗时取决于模型和排队情况。

## 安装条件

- AstrBot 4.28.1 或更新版本。目前验证的消息适配器为 OneBot v11（aiocqhttp）。
- 一个支持图片输入的聊天提供商，用于识图、分类和人格点评。
- 一个支持 OpenAI 兼容 Images edits 接口、支持多图输入（1至2张角色图＋1张食物图）的绘图服务。
- 至少一张角色主参考图，可选再提供一张同一角色的辅助图。

安装插件后，在 AstrBot 后台打开插件常规配置选择服务，再从左侧“插件页面”进入“身临其境的投喂 → 角色与回复定制”。技术包名保留 `astrbot_plugin_feeding`。

## 首次配置

1. 在“角色与回复定制”页面上传 **角色主参考图**（必填，1张）：上传清晰的角色图片，作为外观、服装、画风和人物比例的主要依据。
2. 上传 **角色辅助参考图**（可选，最多1张）：可上传同一角色的另一张图片，补充主图未展示的外观细节；留空也能使用。
3. 每项只保留一张，保存配置。支持 PNG、JPG、JPEG、WebP；单张不超过10MB、2000万像素，处理时缩放至最长1536像素。透明区域会合成白底。
4. 选择 **绘图连接提供商**，完整复用 AstrBot 中已有连接的地址与密钥，再选择生图模型。模型列表按名称筛选，出现在列表里不等于支持所需的多图编辑。
5. **食物识别提供商**可自行选择；留空跟随触发会话的当前聊天提供商，需要支持图片输入。
6. 可填写 **角色补充提示词**，补充具体外观和细节。它不替代 AstrBot 人格，也不移除通用绘图约束。

主图缺失，或者已配置参考图损坏、位置无效或单项上传多张时，插件会在调用模型前提示管理员处理。替换参考图时删除旧上传项，上传新图并保存；已入队任务保留原参考图内容和补充提示词。

## 通用提示词与角色补充

插件根据参考图保持角色外观与画风，并结合本次食物、点评和动作生成画面。辅助图用于补充细节，主图作为主要依据。

在独立页面的大文本编辑区中，角色补充提示词可描述希望保留的角色特征或绘图要求，例如“保留红色围裙和胸前徽章，使用柔和的室内光线”。留空即可根据参考图生成，不需要复制内置提示词。生成效果受模型能力和参考图质量影响。

不要把 API 密钥或其他秘密写在补充提示词中；补充内容会随参考图发送给绘图服务。对话人格仍由 AstrBot 当前会话决定。

插件不附带默认角色参考图、固定角色姓名或私人外观模板。插件头像仅用作标识，不参与绘图。已有实例的数据目录参考图会一次性迁移到上传配置；用户之后删除上传配置，不会自动恢复旧图。

## 定制页面

左侧“插件页面” → 身临其境的投喂 → 角色与回复定制，集中管理参考图、角色补充提示词、点评风格和固定回复。常规配置只保留服务连接、模型、规格、权限和队列。

- 角色补充和点评风格各最多4000字；点评风格默认留空，沿用触发会话人格。
- 固定回复每项最多300字，用于接收、排队、冷却，以及模型未给出点评时的兜底。
- 上传图片后仍需点击“保存修改”；移除或重置也是保存后生效。
- 保存不重载插件，新任务使用新设置；已接收任务保留原文本设置。
- 多个页面同时编辑时，旧页面保存会提示冲突，请先备份自己的文字，再重新载入。
- 现有实例的参考图和角色补充直接保留；页面不会读取或写回 AstrBot 人格，也不会返回 API 密钥。

## 人格与回复

点评使用触发会话在 AstrBot 中当前生效的人格，包括会话人格选择和框架人格解析规则。不单独保存一套插件人格，不要求用户复制人格提示词。公开默认任务规则不强制热情、熟悉关系、回嘴或中文；管理员可自行补充点评风格。

识图请求只发送本次食物图、投喂说明、当前人格和通用任务指令，不主动附带聊天历史。这条独立请求不会自动执行普通聊天的所有插件 hooks。

## 使用

- `#投喂` 与食物图片一起发送。
- 回复食物图片，发送 `#投喂`。
- 可以补充说明，例如 `#投喂 今天自己做的咖喱饭`。
- 管理员发送 `#投喂状态` 查看服务、模型和近24小时任务统计。

命令前缀跟随 AstrBot；这里用 `#` 举例。多图只处理第一张，当前消息图片优先于引用消息。收到后给出简短接收提示，正式点评和成图一同回复。

## 权限与排队

群聊白名单、会话权限和管理员豁免交给 AstrBot 原生流程。插件仅保留 `admin_only`：默认开启，首次验证后可关闭。

所有群聊共享一个处理名额，默认额外等待3个任务，每人冷却60秒。重复消息和同一用户尚未完成的请求不会重复提交；忙碌时使用简短角色口吻提示。插件只限制自身请求，不控制其他客户端调用同一 API。

## 高级连接与生图规格

高级选项中的自定义地址和密钥必须同时填写；两项同时留空时使用所选 AstrBot 提供商。只填一项会拒绝请求，不会混用其他提供商的凭据。

尺寸和质量是向上游提交的请求值，目前没有通用的自动能力检测；能否支持、实际尺寸和耗时由服务决定。默认请求512x512、low，不代表所有模型都支持。模型切换在后台完成，没有切换命令。

## 分类与失败处理

仅明确识别为正常食物才进入生图。危险或恶意投喂按当前人格严肃拒绝；普通非食物或不确定内容会拒绝或追问。分类缺失、格式错误不会放行。图片文字与投喂说明被当作待识别数据；模型判断仍可能出错，不能作为食品安全检测。

绘图不自动重试或切换供应商，避免重复费用。超时后上游可能仍在处理。图片生成后发送失败时保留成图，管理员可取回，不会重新绘制。

## 数据与环境

数据存放在 AstrBot 管理的插件数据目录：

- `files/chibi_reference/`、`files/turnaround_reference/`：后台上传的角色图。
- `inputs/`：临时食物图，处理结束删除。
- `outputs/`：成图保留七天，在后续投喂时清理。
- `tasks.json`：近24小时任务状态、哈希标识、冷却与去重信息，不包含人格正文或密钥。
- 配置由 AstrBot 管理；自定义密钥会保存在配置中，不应公开。

识图服务接收食物图和当前人格；绘图服务接收1至2张角色图、食物图、场景描述、点评和角色补充提示词。请仅配置你信任的服务。

目录使用 AstrBot 路径接口，支持 ASTRBOT_ROOT。Windows 已验证本地路径解析，Linux/Docker 已运行插件回归；macOS和其他适配器尚未实测。其他机器或容器的本地路径不能直接读取，应由适配器提供可访问 URL 或 Base64。

## 开发验证

在已安装 AstrBot 与依赖的 Python 环境中，从插件目录的父目录执行：

```sh
python -m unittest discover -s astrbot_plugin_feeding/tests
```
