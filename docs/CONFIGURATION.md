# 完整配置与环境说明

[返回首页](../README.md)

基于 AstrBot 的 AI 投喂生图插件。结合用户上传的角色设定图和食物图片绘图，沿用触发会话当前生效的人格生成点评，最后将点评与图片放在同一条回复中。每次按本次投喂内容生成，不是预制图库；耗时取决于模型和排队情况。

## 安装条件

- AstrBot 4.28.1 或更新版本。目前验证的消息适配器为 OneBot v11（aiocqhttp）。
- 一个支持图片输入的聊天提供商，用于识图、分类和人格点评。
- 一个支持 OpenAI 兼容 Images edits 接口、支持多图输入（1至2张角色图＋1张食物图）的绘图服务。
- 至少一张角色主参考图，可选再提供一张同一角色的辅助图。

安装插件后，在 AstrBot 后台打开插件常规配置选择服务，再从左侧“插件页面”进入“身临其境的投喂 → 角色与回复定制”。技术包名保留 `astrbot_plugin_feeding`。

## 首次配置

1. 在“角色与回复定制”页面上传 **角色主参考图**（必填，1张）：上传清晰的角色图片，作为外观、服装、画风和人物比例的主要依据。
2. 上传 **角色辅助参考图**（可选，最多1张）：可上传同一角色的另一张图片，补充主图未展示的外观细节；留空也能使用。
3. 每项只保留一张，保存配置。支持 PNG、JPG、JPEG、WebP；单张不超过10MB、2000万像素，处理时缩放至最长1536像素。透明区域会合成白底。
4. 选择 **绘图连接提供商**，完整复用 AstrBot 中已有连接的地址与密钥，再选择生图模型。模型列表按名称筛选，出现在列表里不等于支持所需的多图编辑。
5. **食物识别提供商**可自行选择；留空跟随触发会话的当前聊天提供商，需要支持图片输入。
6. 可填写 **角色补充提示词**，补充具体外观和细节。它不替代 AstrBot 人格，也不移除通用绘图约束。

主图缺失，或者已配置参考图损坏、位置无效或单项上传多张时，插件会在调用模型前提示管理员处理。替换参考图时删除旧上传项，上传新图并保存；已入队任务保留原参考图内容和补充提示词。

## 通用提示词与角色补充

插件根据参考图保持角色外观与画风，并结合本次食物、点评和动作生成画面。辅助图用于补充细节，主图作为主要依据。

在独立页面的大文本编辑区中，角色补充提示词可描述希望保留的角色特征或绘图要求，例如“保留红色围裙和胸前徽章，使用柔和的室内光线”。留空即可根据参考图生成，不需要复制内置提示词。生成效果受模型能力和参考图质量影响。

不要把 API 密钥或其他秘密写在补充提示词中；补充内容会随参考图发送给绘图服务。对话人格仍由 AstrBot 当前会话决定。

插件默认追加大肥鱼抢饭角色，附带参考图、人格和外观补充，可在角色页面修改或删除。主角色的参考图仍需用户上传。默认角色仅初始化一次，不覆盖已有角色；已经修改或删除的角色不会在升级后恢复。插件头像仅用作标识，不参与绘图。已有实例的数据目录参考图会一次性迁移到上传配置；用户之后删除上传配置，不会自动恢复旧图。

## 每日额度与黑名单

在插件常规配置页面设置：

- **每个群每日投喂次数**（`group_daily_limit`）：默认 30，0 表示群与个人均不限。按平台实例与群 ID 分开统计，同群所有普通用户共享额度；私聊不受此项限制。
- **投喂用户黑名单**（`blocked_users`）：列表中每项填写一个账号 ID，QQ 平台填写 QQ 号，不填昵称。对所有群和私聊生效，明确列入黑名单的管理员也会被阻止。

每位普通用户在每个群内另有个人额度，等于群上限的20%，向下取整且至少1次。例如群上限30→每人6，50→每人10，34→每人6。个人计数随群分别保存，不会因为在另一个群投喂而消耗本群个人额度；管理员豁免，私聊不受此限制。调整群上限后个人额度随之改变，已有当天计数不清零。

额度每天按北京时间（UTC+8）零点重置，不依赖服务器时区。成功入队即占用一次，之后识别拒绝、下载或绘图失败也计次；缺图、配置错误、重复消息、冷却中及队列满等未入队请求不计次。当天记录随任务日志持久化，重启不会清空。升级前的旧任务没有额度字段，不追溯计数。

AstrBot 管理员不消耗每日额度，但仍遵循原有队列、冷却、消息去重和 AstrBot 权限规则。修改限额后下一次投喂使用新限额，已入队任务继续执行；黑名单也不会取消已接收的任务。配置为不限次数期间仍记录普通用户的群投喂次数，重新启用限额时按当天累计次数判断。

## 定制页面入口

左侧“插件页面” → 身临其境的投喂 → 角色与回复定制，集中管理参考图、角色补充提示词、点评风格和固定回复。常规配置管理服务连接、模型、规格、权限、额度和队列，也提供抢饭总开关与分配方式；角色列表及概率预览在独立页面中管理。

- 角色补充和点评风格各最多4000字；点评风格默认留空，沿用触发会话人格。
- 固定回复每项最多300字，用于接收、排队、冷却，以及模型未给出点评时的兜底。
- 上传图片后仍需点击“保存修改”；移除或重置也是保存后生效。
- 保存不重载插件，新任务使用新设置；已接收任务保留原文本设置。
- 多个页面同时编辑时，旧页面保存会提示冲突，请先备份自己的文字，再重新载入。
- 现有实例的参考图和角色补充直接保留；页面不会读取或写回 AstrBot 人格，也不会返回 API 密钥。

## 人格与回复

主角色点评使用触发会话在 AstrBot 中当前生效的人格，包括会话人格选择和框架人格解析规则，不要求用户复制主角色人格提示词。公开默认任务规则不强制热情、熟悉关系、回嘴或中文；管理员可自行补充点评风格。抢饭角色使用管理员单独填写的人格，仅作用于本次正常食物的抢饭回应，不改变 AstrBot 人格。

识图请求发送本次食物图、投喂说明、当前人格和通用任务指令；抢饭候选还会包含抢饭人格。不主动附带聊天历史。这条独立请求不会自动执行普通聊天的所有插件 hooks。

## 多角色抢饭

在独立定制页面管理 `guest_roles` 列表。每项包含角色名称、启用开关、随机出场开关、自定义概率、独立人格（最多6000字）、抢饭提醒（最多300字，留空关闭）、外观补充（最多4000字）、一张主参考图及一张可选辅助参考图。上传限制沿用10MB和2000万像素。

- `steal_enabled`：随机抢饭开关，默认关闭。
- `steal_mode`：`average` 为平均分配，`custom` 为自定义分配。
- `steal_probability`：平均模式的总抢饭概率，0–100，默认15；自定义模式不使用此值。
- 平均分配：总概率由已启用、参与随机且配置完整的角色平分。
- 自定义分配：各角色填写在全部正常投喂中的最终概率，剩余概率留给原角色。启用且参与随机的角色概率之和不能超过100%；未配置完整的角色暂不出场，不把它的概率转给其他抢饭角色。
- 关闭随机出场或设置自定义概率0%，仍可管理员指定；停用、缺人格或参考图无效时不可指定。
- 管理员指令：`#投喂角色名 [情境说明]`，例如 `#投喂千小妹 这份给你`，附带或引用食物图片。角色保存后立即可用；旧写法 `#投喂角色 角色名` 仍兼容。“角色”和“状态”为保留名称。

抢饭提醒在生图完成后作为单独一条消息发出，随后紧接着发送点评与图片。拒绝、非食物和生图失败不发送抢饭提醒。两次发送都沿用现有失败处理，不自动重试，避免重复提醒或重复付费绘图。默认提醒为“刚递过去，就被半路接走了……”，可按角色修改。

所有配置与文件仍保存在 AstrBot 插件数据目录。旧单角色自动迁移一次，保留原资料及总概率，旧字段留作兼容备份但不再参与选择。页面修改只影响新任务，已经接单的任务保留选定角色及参考图；删除角色不立即删除已上传图片。

## 使用

- `#投喂` 与食物图片一起发送。
- 回复食物图片，发送 `#投喂`。
- 可以补充说明，例如 `#投喂 今天自己做的咖喱饭`。
- 管理员发送 `#投喂状态` 查看服务、模型和近24小时任务统计。

命令前缀跟随 AstrBot；这里用 `#` 举例。多图只处理第一张，当前消息图片优先于引用消息。收到后给出简短接收提示，正式点评和成图一同回复。

## 权限与排队

群聊白名单、会话权限和管理员豁免交给 AstrBot 原生流程。`admin_only` 默认开启，首次验证后可关闭；在 AstrBot 权限检查之外，插件还会检查黑名单、群与个人每日额度。

所有群聊共享一个处理名额，默认额外等待3个任务，每人冷却60秒。重复消息和同一用户尚未完成的请求不会重复提交；忙碌时使用简短角色口吻提示。插件只限制自身请求，不控制其他客户端调用同一 API。

## 高级连接与生图规格

高级选项中的自定义地址和密钥必须同时填写；两项同时留空时使用所选 AstrBot 提供商。只填一项会拒绝请求，不会混用其他提供商的凭据。

尺寸和质量是向上游提交的请求值，目前没有通用的自动能力检测；能否支持、实际尺寸和耗时由服务决定。默认请求512x512、low，不代表所有模型都支持。模型切换在后台完成，没有切换命令。

## 分类与失败处理

仅明确识别为正常食物才进入生图。危险或恶意投喂按当前人格严肃拒绝；普通非食物或不确定内容会拒绝或追问。分类缺失、格式错误不会放行。图片文字与投喂说明被当作待识别数据；模型判断仍可能出错，不能作为食品安全检测。

绘图不自动重试或切换供应商，避免重复费用。超时后上游可能仍在处理。图片生成后发送失败时保留成图，管理员可取回，不会重新绘制。

## 数据与环境

数据存放在 AstrBot 管理的插件数据目录：

- `files/chibi_reference/`、`files/turnaround_reference/`：后台上传的角色图。
- `files/guest_reference/`：各抢饭角色上传的主／辅助参考图，删除角色不会立即删除文件。
- `inputs/`：临时食物图，处理结束删除。
- `outputs/`：成图保留七天，在后续投喂时清理。
- `tasks.json`：近24小时任务状态、哈希标识、冷却、去重及群／个人每日额度信息，不包含人格正文或密钥。
- 配置由 AstrBot 管理；自定义密钥会保存在配置中，不应公开。

识图服务接收食物图和当前人格，抢饭候选还包含选中角色的人格；绘图服务接收1至2张角色图、食物图、场景描述、点评和角色补充提示词。请仅配置你信任的服务。

目录使用 AstrBot 路径接口，支持 ASTRBOT_ROOT。Windows 已验证本地路径解析，Linux/Docker 已运行插件回归；macOS和其他适配器尚未实测。其他机器或容器的本地路径不能直接读取，应由适配器提供可访问 URL 或 Base64。

## 升级与默认值

覆盖更新插件代码，保留 `data/config/astrbot_plugin_feeding_config.json` 与 `data/plugin_data/astrbot_plugin_feeding/`。旧单角色只迁移一次，删除后不自动恢复。已有群额度保持原值，30是新默认值；需要调整时在后台保存。已有当天带群字段的记录也参与个人额度统计，升级不重置当天计数。升级后重新进入插件页面，避免旧页面提交过期字段。

## 开发验证

在已安装 AstrBot 与依赖的 Python 环境中，从插件目录的父目录执行：

```sh
python -m unittest discover -s astrbot_plugin_feeding/tests
```

页面交互回归可从插件目录执行 `node --test tests/test_customize.cjs`（仅开发测试需要 Node.js）。

测试模拟模型与发送接口，不调用真实付费模型。项目代码采用 AGPL-3.0，作者为 Mikakei。不要将用户上传图片、实例配置、备份或部署凭据加入仓库。
